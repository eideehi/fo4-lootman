# Fallout 4 1.11.240 Migration Status

Date: 2026-08-23

## Status

Static native-hook migration evidence and production integration are complete
for Fallout 4 `1.11.240`. The production manifest, generated header,
CommonLibF4 checkpoint, installer, and user guide now target `1.11.240`.

The remaining release gate is an F4SE load and native-hook installation smoke
test against the exact executable recorded below.

## Stale-Baseline Check

The production `1.11.221` manifest contains 58 selected direct-call sites.
Reading those RVAs from the `1.11.240` executable found:

- two sites whose first byte was still `E8`
- zero sites whose decoded target still matched the manifest
- zero sites whose stored post-call context still matched

The existing runtime authentication therefore rejects the stale sites instead
of patching them. This observation describes the pre-migration `1.11.221`
production DLL; the integrated `1.11.240` DLL build is recorded below.

## Static Migration Result

The versioned Ghidra reports in
`tools/ghidra/reports/fallout4-1.11.240/` prove:

- 15 direct-call hook families
- 58 selected direct-call sites
- one explicitly excluded internal fallback call in
  `workshop_material.direct_component_count`
- the expected selected-site count for every family
- a five-byte `E8 CALL rel32` to the expected family target at every selected

## Candidate Verification

The candidate was first applied and verified in an isolated clone, then
promoted to the production manifest after the dependency gates were satisfied.

The isolated verification sequence completed as follows:

1. Generate a candidate header from the `1.11.240` manifest.
2. Run the resolver without `--write` against
   `tools/ghidra/reports/fallout4-1.11.240/proven-call-site-evidence.txt`.
3. Run the resolver with `--write` in the isolated clone.
4. Point the isolated verifier default at the `1.11.240` aggregate evidence.
5. Run `verify-native-hooks.ts`.
6. Generate the review bundle in this directory.

Results:

- resolver: 15 proven entries resolved
- selected sites: 58
- excluded same-target references: one
- manifest/header verifier: pass
- review-bundle direct-call counts: pass for every family

The production manifest declares the aggregate raw-byte report through
`resolutionEvidenceReport`. The resolver rejects an override that does not
match that declaration, rejects malformed lines after a raw-byte window starts,
and derives context signatures only from instructions contiguous with the
selected `E8 CALL rel32` site.

The review-bundle parser needed a production tooling fix so it recognizes the
current raw-byte Ghidra line format:

```text
address: [E8 xx xx xx xx] CALL target
```

That parser fix and its regression test are separate from the candidate
manifest and are safe for the existing `1.11.221` production state.

## Dependency Gates

As observed on 2026-08-23:

- F4SE build `0.7.9` supports Fallout 4 runtime `1.11.240`.
- The installed game directory contains `f4se_1_11_240.dll` with SHA-256
  `25759ed8fb110ff3ce79f174d2acf15aa82834179d9e69c53d3fb9f59176a2ef`.
- The installed Address Library contains `version-1-11-240-0.bin`. Parsing its
  V0 `count + { id, offset }` records using the CommonLibF4 loader contract
  confirms all five candidate mappings exactly:
  - `2200355` -> `0x4D3150`
  - `4797310` -> `0x30F7AB8`
  - `4797241` -> `0x30F7698`
  - `2195024` -> `0x389DB0`
  - `4797160` -> `0x30F6F18`
- CommonLibF4 checkpoint
  `d5fb20b72d9a2ed8f092ccf4ffa664d3a4a9ece1` defines
  `F4SE::RUNTIME_LATEST = RUNTIME_1_11_240`.
- CommonLibF4's plugin template exports
  `CompatibleVersions({ F4SE::RUNTIME_LATEST })`.

Because LootMan is layout-dependent and uses CommonLibF4 relocations beyond the
custom hook manifest, changing only the custom RVAs or only the exported
compatible-version list would create false compatibility. F4SE, Address
Library, and CommonLibF4 now all target `1.11.240`. The staged WSL-to-Windows
DLL build completed successfully, and its generated plugin metadata uses
`CompatibleVersions({ F4SE::RUNTIME_LATEST })` with `RUNTIME_LATEST` equal to
`1.11.240`.
